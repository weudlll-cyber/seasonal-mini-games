# Audit

Full audits of the repository (owner decision O129), newest first, one section per area. Each finding has its evidence (file and line at the audit's commit, a run or a measurement), what was done, and for what was not done a proposal. The rule for every finding: it is fixed when it is provably wrong, dead or stale, or a defect whose fix changes nothing players see or do; anything that would change what players see or do, or that needs a decision, is not changed and goes to [OPEN.md](OPEN.md) as an owner question with the proposal.

## 2026-11-22 — night chain 2026-11-22 (master `fb66746` and the merges after it)

### Correctness (B2, branch `chore/audit-correctness`)

The round engine (04 §5, 03, 06 §2.3–§2.5) read against its code: `packages/domain/src/round`, `packages/application/src/round`, `apps/server/src/round`, `match/series.ts`, `realtime/gateway.ts`, the migrations.

Held as specified (no change):

- **Ordering.** Every event gets the next seq as it is processed (`round/actor.ts` `stamp`); batches commit one after the other on one promise chain, and a batch's replies and frames go out only after its `append` resolved (`commit`). `receiveSeq` is the state's last plus one in queue order (`packages/domain/src/round/guess.ts`, `phased.ts`), so it has no gap.
- **Frost** holds an event only if its delivery time is still ahead at the commit and releases it once it is due, after the batch that records the release committed (`round/frost.ts`, `actor.ts` `release`); after a restart the log's undelivered events come back (`pgRoundStore.ts` `load`, `gameRunner.ts` `recover`).
- **The hold before the result** is part of the round's longest time (`packages/game-sdk/src/roundSettings.ts`, `resultHoldMs`), so `round_time_up` and the catch-up end both include it.
- **Timers.** The actor's due timer, Frost's timer, the delayed room's interval and last-second timers, the scheduler, the guess limits and the idle close are all cleared on stop, and none fires after a round ended.
- **A restart mid-round** catches up: the recovered actor arms its due timer at once for a time already passed, `catchUp` stamps the open and the end at their own times, and a late `round_open` or `round_time_up` row is refused and marked done.
- **Migrations.** Every integration test file migrates an empty database (`apps/server/test/harness.ts`); `server.integration.test.ts` checks that each migration is recorded and a second run applies nothing; the runner keeps each file's checksum and refuses a changed one (`db/migrator.ts`). Data migrations are re-run on a migrated database in `resultWon.integration.test.ts` (0016) and `adminHistory.integration.test.ts` (0021).

Not changed, with a proposal:

- **A view can show what has not committed yet.** `GET /rounds/:id/state` reads the actor's current state, which includes the open batch (`round/liveRound.ts` `view`); after a failed commit a solve shown there can go away again. Proposal: leave as is (a failed commit is rare and the round rebuilds at once); if it matters, views read the state as of the last committed batch.
- **The shutdown closes the sockets before the rounds drain** (`main.ts`: `io.close()`, then the server and the runtime): acknowledgements of the last batches cannot be sent, and clients resend into `ALREADY_GUESSED` or a cooldown. Proposal: drain the rounds before closing the sockets.
- **Ended rounds stay in memory** (`round/rounds.ts`, the live map never removes one). Proposal: drop a round from the map a while after its end, once its frames and its result were sent.
- **Two instances starting at once could race on a migration** (`db/migrator.ts` has no advisory lock; the loser fails on the record's key and rolls back). One instance is the supported setup (04 §5.6). Proposal: take an advisory lock around the run when scale-out is built.
- **No test upgrades a database at the previous version** (0021 → 0022 and so on): each test migrates an empty one. Proposal: a test that migrates to the previous version, writes rows, and applies the last migration.
